[フェーズ4] 設定スキーマ・設定画面・CLI での設定・全操作のキー割り当て

## ユーザーの発言（原文）
- 「キーとかも好きに色々設定できるように」
- 「あと、AIエージェントにいえば、設定とか自然言語で変えられるようにして欲しい」
- 「キー割り当てとか、全部結構自由に変えられるようにして欲しい」
- 「UIを貼り付け時に出すかとか」

詳細は `.agent/requirements.md` を正とする（差別化 3・「設定は最初から AI が操作できる作りにする」）。

## 決まったこと（2026-10-31）
- **設定スキーマを画面と CLI/MCP で共有する**。設定項目の一覧（スキーマ）を 1 つだけ持ち、項目ごとに ID・型・既定値・取りうる値・人が読める説明を持たせる。AI が自然言語の頼みを該当の項目に結びつけられるようにする
- **設定を CLI で読み書きする口は、フェーズ6 を待たずにこのフェーズで作る**（MCP はフェーズ6 で同じスキーマを使う）
- 設定には秘密を入れない。AI が読むのも書くのもよい。履歴の中身はこれまでどおり AI に見せない
- キーは全部自由に変えられる: 呼び出し・候補窓の ↑↓/Tab/Esc/広げる・一覧の中の操作・絞り込みの切り替えのすべて。重なったキーを検出する
- ⌃⌘V の動きを「すぐ貼るだけ／すぐ貼って候補窓／一覧を開く」から選べる（貼り付けのときに UI を出すか）。既定の ⌃⌘V は Clipy の「履歴を開く」と同じなので、キー自体も変えられる

## 範囲
- 設定スキーマ（Core）・設定の保存と検証（Core）・設定画面・CLI（例: `Makurip --settings list|get|set`）
- 全操作のキー割り当てと重なりの検出、キーを記録する UI（KeyboardShortcuts ライブラリは記録 UI 付きの候補。入れるなら理由と代替を PR と AGENTS.md に書く）

## フェーズ1 の作りから寄せられるか（所見・実装はしていない）

結論: 寄せられる。いまは設定の保存先がなく、値は型の既定値として 1 か所ずつにまとまっているので、スキーマを足して既定値の出どころをそこへ移せばよい。直書きのキーが 2 か所ある。

そのまま使えるもの:
- 上限は `Limits`（Codable の構造体）の 1 か所に集まっている。`ClipStore(directory:limits:)` と `PasteboardMonitor(limits:)` に渡しているだけなので、出どころを設定に替えられる
- グローバルショートカットは `HotKey`（仮想キーコード + 修飾キー、Codable）で、`HotKeyCenter.register` / `unregister` は動いている最中に付け替えられる（Carbon `RegisterEventHotKey`。任意の組み合わせを登録でき、権限も要らない）
- データフォルダは `--data-dir` で切り替えられるので、設定ファイルもデータフォルダに置けば、検証用に隔離したインスタンスの設定が本物と混ざらない

直す・足すもの:
1. **スキーマと保存先**: `SettingsSchema`（項目の ID・型・既定値・範囲・説明）と、その値を読み書きする層を Core に足す。保存先は UserDefaults よりデータフォルダの JSON ファイルが向く（CLI がアプリと同じコードで読み書きでき、隔離もできる）。検証（範囲・型・キーの重なり）は Core の 1 か所で行い、画面と CLI が同じ関数を通す
2. **動いているアプリへの反映**: CLI が書き換えたら、動いているアプリに読み直させる仕組みが要る（ファイルの監視か、分散通知）。いまの検証用の遠隔操作（`--debug-control`）は隔離時だけ有効なので、そのまま使わず本番用の口を別に作る
3. **`ClipStore.limits` が `let`**: 動いている最中に上限を変えるなら `var`（ロックで守る）にするか、変更時に `enforceLimits` を呼び直す形にする
4. **直書きのキー**: 一覧の中の ↑↓・Enter・Esc は `ProvisionalHistoryPanel.handleKey` の仮想キーコード直書き（フェーズ2 で UI ごと差し替わる）。メニューの「履歴を開く」の表示も `StatusMenuController` で ⌃⌘V を直書きしている。どちらも「操作 ID → キー」の表から引く形にする
5. **⌃⌘V の動きの切り替え**: いまはホットキーの処理が `AppController.toggleHistory` に固定。設定の値で「すぐ貼る／すぐ貼って候補窓／一覧を開く」に分ける入口を作る（候補窓は #8）
6. **設定にしてはいけないもの**: ConcealedType 等を保存しない動きなど、プライバシーを守る振る舞いはスキーマに入れない（ほかのプロセスでも設定ファイルは書き換えられる。AI や他のアプリが「パスワードも保存する」にできないようにする）
7. **内部の定数**: 監視の間隔（0.25 秒）・落ち着くまでの待ち（0.08 秒）・コピー方法の窓（1.0 秒）・一覧に読む件数（500）は、ユーザー向けの設定にしなくてよい（出すなら「詳細」扱い）
