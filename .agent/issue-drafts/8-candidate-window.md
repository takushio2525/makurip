[フェーズ2.5] 候補窓（予測変換のような貼り付けと ↑↓ での差し替え）

## ユーザーの発言（原文）
- 「あと，ターミナルみたいに，control+Vで貼り付けた後は，上下のやじるしキーで履歴を一個ずつロールできるというか，予測変換みたいな形式で コレみたいなのが出てくるようにしてほしいな」
- 「コントロールVで追加窓になる感じで」
- （添付は macOS の日本語入力の予測変換の候補窓。最下段に「Tabキーで選択」）

詳細は `.agent/requirements.md` を正とする。フェーズ2 の後に置く（番号は起票順の都合で #8）。

## 決まったこと（2026-10-31）
- ⌃⌘V は最終的に、押すとすぐ最新の履歴を貼り、文字カーソルのすぐ下に予測変換のような候補窓を出す
- 候補窓では、↑↓ で貼った中身が前・後の履歴に差し替わり、Tab で確定、Esc で取り消して貼る前に戻す。1 キーで大きい一覧へ広げられる
- キーは設定で変えられる（フェーズ4）
- フェーズ1 では ⌃⌘V は仮の一覧を開くまま

## 技術的な要点
- 文字カーソルの位置は AX（`AXSelectedTextRange` → `AXBoundsForRange`）で取る。取れないアプリ（ターミナルや Electron 製）では、マウスの位置などで代わりにする
- 候補窓を出している間だけ、↑↓・Tab・Esc を CGEventTap で横取りする
- 日本語入力の変換中は横取りしない
- 差し替えは、直前に貼った範囲を選び直して貼るか、⌘Z を使う（アプリによって挙動が違う）

## フェーズ1 の作りから広げられるか（所見・実装はしていない）

結論: データモデルとスキーマは変えずに広げられる。貼り付けの流れは 4 か所を分ける・足す必要がある。

そのまま使えるもの:
- `ClipStore.items(limit:)`（新しい順）と `snapshot(id:)`（全型）で、前後の履歴の中身をすぐ取れる。スキーマの変更は要らない
- `PasteboardWriter.write` + `PasteboardMonitor.acknowledgeOwnWrite` で、差し替えのたびの書き戻しも新しい履歴にならない
- `Paster.postCommandV(to:)` は pid 宛てなので、前面のアプリにだけ ⌘V を送れる
- `HotKeyCenter` は `Action` を足せば「すぐ貼る」動きを登録できる。`HotKey` は Codable で設定に保存できる

直す・足すもの:
1. **先頭へ移すのを確定まで遅らせる**: `AppController.paste(itemID:)` は書き戻しと同時に `store.touch` で先頭へ移す。↑↓ で回すたびに並びが変わってしまうので、「仮に貼る（touch しない）」と「確定（Tab で touch）」に分ける。回している間は、始めた時点の ID の並びを固定して持つ
2. **activate しない送り方と ⌘Z**: `Paster.paste(into:)` は宛先を activate してから送る。候補窓は前面のアプリからフォーカスを奪わない（`.nonactivatingPanel`）ので、activate せずに前面の pid へ送る口と、⌘Z を送る口を足す
3. **一覧とは別の UI の約束**: 仮の一覧（`HistoryPresenting`）は Makurip を前面にしてキーを受ける作り。候補窓は別のプロトコル（例: 文字カーソルの矩形に出す・選択を更新・閉じる）にして、一覧と混ぜない
4. **取り消し用の状態をメモリに持つ**: Esc で「貼る前に戻す」には、始める前のペーストボードの全型（`PasteboardReader.read` の結果）を持っておき、取り消しのあとで書き戻す。セッションの状態（元のペーストボード・固定した並び・いまの位置・直前に貼った範囲）は保存しない

落とし穴（要調査）:
- **差し替えの方式**: 貼る前後の `AXSelectedTextRange` が読めれば、貼った範囲 {前の位置, 長さ} を選び直して ⌘V。読めないアプリでは ⌘Z → ⌘V。画像・リッチテキストは範囲の長さが文字数と一致しない（添付は 1 文字）ので ⌘Z 寄り。⌘Z が「貼り付け」以外の直前の操作まで戻すアプリもある
- **ターミナル**: 改行を含む中身を貼るとその場で実行されうる（bracketed paste が無効なシェル）、⌘Z が効かない。文字カーソルが AX で取れないアプリでは、↑↓ の間は貼らずに候補窓で中身を見せるだけにし、Tab で初めて貼る、などの別扱いが要りそう
- **横取りのタップ**: 能動の CGEventTap はアクセシビリティの許可で作れる見込み（入力監視の許可が別に要るかは要確認）。候補窓を出している間だけ有効にし、閉じたら必ず外す（外し忘れると ↑↓ が効かなくなる）。`kCGEventTapDisabledByTimeout` で無効化されたら付け直す
- **変換中の判定**: 未確定文字（マークされた範囲）の有無は、AX の標準属性では取れないアプリが多い。入力ソースが日本語入力かどうか（`TISCopyCurrentKeyboardInputSource`）などからの近似になる
- コピー方法の判定（⌘C / ⌘X の監視）には影響しない
