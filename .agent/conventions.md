# 規約（命名・ログ・エラー・テスト・判定の限界）

## 命名

| 対象 | 規則 | 例 |
|---|---|---|
| ファイル | 中心の型の名前（PascalCase） | `ClipStore.swift` |
| 型 | PascalCase | `PasteboardSnapshot` |
| 関数・変数 | camelCase | `acknowledgeOwnWrite` |
| DB の表・列 | snake_case | `last_used_at` |
| 起動引数 | `--kebab-case` | `--data-dir` |
| 分散通知（検証用） | `com.takushio2525.makurip.debug.<命令>` | `...debug.toggleHistory` |

UI に出す文言は日本語。絵文字は使わない。

## ログ（最重要: 中身を書かない）

- `os.Logger`（サブシステム = バンドル ID、カテゴリ `app` / `capture` / `paste`）
- 書いてよいのは **メタデータだけ**: 種類・コピー方法・型の数・バイト数・スキップの理由・結果
- **平文・データ・プレビュー・コピー元ページの URL は書かない**。`privacy: .public` を付けるのはメタデータの値だけ
- 見るとき: `log stream --predicate 'subsystem == "com.takushio2525.makurip"' --info`

## エラー

- ストア・SQLite は `throws`（`SQLiteDatabase.Failure`）。呼ぶ側（アプリ）はログに残して続ける。起動時に開けなければ終了する
- 取り込みの失敗は `PasteboardMonitor.Event.failed` で返す（落とさない）

## テスト

- 単体テストは Swift Testing（`@Test` / `#expect`）。`swift test` で全部回る
- **一般ペーストボードを使わない**。`NSPasteboard(name:)` に一意な名前を付け、終わったら `releaseGlobally()`
- ストアのテストは一時フォルダ（`TemporaryDirectory`）。既定のデータフォルダに触らない
- テストデータは自作（`Tests/MakuripCoreTests/Fixtures.swift`・`MakuripDevTool pb-write`）
- E2E（`scripts/e2e/`）は `--data-dir` で隔離し、終わったら消す。起動したインスタンスは必ず終了させる
- UI のテスト（`MakuripUITests`）は `@MainActor` で動く。重い処理（大きい画像を作る等）をテストごとにメインで行わない。
  ペーストボード監視のテストはメインの 0.05 秒後のタイマーを 400 ms 以内に待つので、メインを塞ぐと落ちる
- 見た目の検証（`SnapshotTests`）と速さの計測は環境変数 `MAKURIP_SNAPSHOT_DIR` を付けたときだけ動く（`make ui-compare`）

## 判定の限界（正直に書く）

### 種類（`KindClassifier` / `TextHeuristics`）

経験則なので、次は見分けられない・間違えうる。

- **短い断片**: 「`x = 1`」のような 1 行は、手がかりが 2 つ以上ないとコードにならない。逆に「`a == b`」を含む文章はコードになりうる
- **コードを含む Markdown**: 途中に ``` がある文書はテキスト扱い（AI チャットの回答をまるごとコピーした場合など）。全体が ``` で囲まれていればコード
- **コマンド**: 先頭の語が既知の CLI の一覧（`TextHeuristics.knownCommands`）にあるか、1 行目がプロンプト（`$ ` `% ` `❯ ` `➜ `・`user@host:~$ ` などの PS1）で始まるときだけ。一覧にない自作のツールは「テキスト」になる。
  root の `# ` は、**全部の行が「# 既知のコマンド …」のときだけ**コマンドにする（「# 見出し」「# コメント」と区別するため）。「# make targets」のように見出しの頭が小文字の既知のコマンドだと、コマンドになってしまう（Markdown の見出しはふつう大文字か日本語で始まるので許した）
- **SQL・YAML・HTML（フェーズ3）**: SQL は頭のキーワードが大文字か、行末が「;」のときだけ（「Select the best option」のような英文を外す）。YAML は `key:` の行が 2 つ以上あり、入れ子の `key:`・`- ` の並び・`---` のどれかがあるもの（「Note: …」の並びは外れる）。HTML・XML はタグで始まりタグで閉じ、閉じタグがあるもの
- **リッチテキスト**: RTF・HTML の型が載っているかで決める。VS Code やターミナルは色付きの RTF/HTML も載せるが、中身がコード・コマンドならそちらを優先する。整形のない文章でも RTF を載せるアプリ（Pages 等）はリッチテキストになる
- **画像と文章が両方あるとき**: Office は文章にプレビュー画像（PNG/PDF）を添えるので、文章があればリッチテキスト。平文が URL かパスだけなら画像（ブラウザの「画像をコピー」）
- **PDF だけ**: 画像として扱う（種類に PDF がないため）
- **色**: 色の型（`com.apple.cocoa.pasteboard.color`）か、`#RRGGBB` / `rgb()` / `hsl()` の 1 語だけ。色名（`red`）は色にしない
- **ファイル**: `file://` の URL があれば何があってもファイル（Finder はアイコン画像と名前の平文も載せるため）

### コピー方法（`CopyMethodClassifier`）

- **キー操作の判定にはアクセシビリティの許可が要る**。許可がないあいだは全部「不明」（「それ以外」と混ぜない）
- ⌘C を押したが何もコピーされず、1 秒以内にボタンでコピーすると「キー操作」になる
- ⌘C から 1 秒より遅れてペーストボードに書くアプリは「それ以外」になる
- ⌘C を他のキーに割り当てているアプリ、メニューの「コピー」をマウスで選んだ場合は「それ以外」（正しい）
- 自動操作（他のプロセスが `postToPid` で送った ⌘C）はグローバル監視に見えないので「それ以外」
- セキュア入力中（パスワード欄など）はキーが見えない（その場合、コピー自体もふつう ConcealedType が付く）
- ⌃ を伴う ⌃⌘C などは別の操作とみなす

### 取り込み（`PasteboardMonitor`）

- ペーストボードには変化の通知がないので 0.25 秒おきに見る。**それより速く上書きされたコピーは最後の 1 回だけ**になる（上書きされた中身は読みようがない）。書き込みが落ち着くまで 0.08 秒待つので、0.3 秒より短い間隔の連続コピーはまとまる
- コピー元のアプリは「変化を見つけた時点で前面にいたアプリ」（⌘C のときは押した瞬間）。コピーしてすぐ別のアプリへ切り替えると、切り替え先になることがある。バックグラウンドのアプリが書いた場合も前面のアプリになる
- 遅延で渡すデータ（promise）は読んだ時点で書き手に作らせる。書き手が終了していると読めない型は落ちる
- 同じ内容の判定は「全項目・全型のデータが同じ」（コピーのたびに変わる付随情報の型は除く。`PasteboardMarkers.volatileTypePrefixes`）。同じ文字列でもコピー元のアプリが違って型の組が違えば別の履歴になる
- コピー元ページの URL は Chromium 系（`org.chromium.source-url`）と WebKit の webarchive だけ。Firefox・コピーボタン（`navigator.clipboard.writeText`）は取れない

### 貼り付け（`Paster`）

- ⌘V は仮想キーコード 9 + 文字 "v" で送る。⌘V を別のキーに割り当てているアプリでは貼れない
- 元のアプリが終了していたら ⌘V は送らない（ペーストボードには載っている）

### 検索（`SearchText` / `HistoryFilter`）

- 探す対象は一覧の平文（先頭 1000 文字）・アプリ名・種類名・コピー元ページのホスト名。**1000 文字より後ろの文章は検索に入らない**（プレビューでは全文を出す）。画像の中の文字も探さない
- 漢字は読みで引けない（「てじゅん」で「手順」は出ない）。ローマ字が効くのは、英字だけで 2 文字以上の語をかなとして読める場合だけ。英語の語は綴りのまま一致する（読みの候補を足すだけ）
- ローマ字の読みは 1 通り（「si」も「shi」も「し」）。「n」の直後に母音・y が来ると「な行」になる（「kani」は「かに」。「かんい」は「kan'i」と打つ。子音の前の「nn」は「ん」1 つ）
- 開いて 0.2 秒以内に打つと、検索用の正規化がまだ済んでおらず、1 回目の打鍵だけ遅い（5000 件で 0.24 秒）

### パネルの位置（`InsertionPointLocator` / `PanelPlacement`）

- 文字カーソルは AX で取る。アクセシビリティの許可がないとき、ターミナル・Electron 製（VS Code・Slack 等）・一部の Web の入力欄は取れないことが多く、入力欄の枠 → マウスの位置の順で代わりにする
- 入力欄の枠しか取れないアプリでは、枠の左下を基準にする（大きいテキストビューだと、書いている行から離れた所に出る）
- 問い合わせの待ちは 0.15 秒で切る（応答しないアプリで止まらないように）

### 候補窓（`CandidateCoordinator` / `KeyEventTap` / `ReplacePlanner`）

**横取りを残さないための決まり**（いちばん大事。変えるときは `CandidateInterceptLifetimeTests` に経路を足す）

- タップを作るのは `CandidateCoordinator.start` だけ。閉じる経路（⇥・↩・esc・広げる・ほかのキー・窓の外のクリック・ダブルクリック・
  10 秒の無操作・前面のアプリの切り替え・窓が閉じられた・スペースの切り替え・画面のスリープ・ログアウト画面・画面の構成の変化・
  タップが止められた・差し替えの失敗・Makurip の終了）はすべて `end` を通り、その場でタップを止める。文書の後始末はその後で、タップなしで行う
- システムがタップを止めたら（`tapDisabledByTimeout`・`tapDisabledByUserInput`）**付け直さない**。候補窓を閉じる。
  応答が遅れた状態で横取りを続けると、キーが届かないまま食べられうるため
- Makurip が落ちたときは、タップの mach port がプロセスと一緒に消えるので、横取りも消える（OS の仕組み。テストでは確かめられない）。
  固まったときは、システムがタップを止める（上と同じ）
- タップの中の処理は短く（AX の問い合わせは 0.1 秒で切る）。文書への反映は別の流れ（`drain`）で行う
- Makurip が送ったキー（⌘V・⌘Z・⌘⇧Z・⌫）には印（`SyntheticEventMarker`）を付け、タップはそれを見ずに素通しする

**変換中**

- 判定は、AX の未確定の範囲（`AXTextInputMarkedRange`。WebKit は `AXTextInputMarkedTextMarkerRange`）。読めなければ入力ソースで近似する
  （日本語入力のかなモードなど英字以外 → **判定できない**。英字・ふつうの配列 → 変換中ではない）
- 変換中に ⌃⌘V を押したら: 仮に貼らない（確定まで貼らない方式）。変換が終わるまでは ↑↓・⇥・↩・esc も横取りしない（日本語入力のもの）
- 判定できないときは**安全側**: 仮に貼らない（未確定の文字があるところへ ⌘V を送ると、確定のされ方がアプリで違うため）。
  キーは横取りする（取り消しは esc でいつでもでき、確定するまで文書に何も送らないので、間違って横取りしても文書は変わらない）
- 候補窓の間に文字のキーを押すと、そこで確定して閉じ、そのキーは前面のアプリへ渡る。なので候補窓と日本語入力の変換が同時に起きることはない

**差し替え**

- 方式は「範囲を選び直す → ⌘Z → 確定まで貼らない」の順。どれも**結果を AX で確かめられるときだけ**使う。入力欄の選択範囲を
  AX で読めないアプリ（ターミナル・多くの Electron 製・入力欄でない所）では仮に貼らない（⌘Z を確かめずに送ると、Finder などで別の操作を取り消すため）
- 範囲の選び直しは、文字だけの中身で、貼る前後の文字カーソルから測った長さが中身の文字数（UTF-16）と同じときだけ。
  改行の変換・自動の字下げ・スマート引用符などで長さが変わるアプリ、画像・リッチテキストは ⌘Z
- 始めに文字を選んでいたら ⌘Z（貼り付けが選択を置き換えるので、範囲を消しても元の文字は戻らない）
- ⌘Z で戻ったかは「選択の位置と文字数が貼る前と同じか」で見る。戻らなければ ⌘⇧Z で打ち消して、貼ってあるもので閉じる。
  失敗した方式はアプリごとにメモリで覚え、次からはその次の方式で始める（再起動で忘れる。決め打ちは `candReplaceMethod`）
- 範囲を選び直して差し替えたあとの取り消しは「範囲を選んで ⌫」なので、相手のアプリの取り消しの履歴には途中の差し替えが残る
- 取り消し・広げるの後始末（⌘Z など）は数十〜数百 ms かかる。その間に打った文字は、後始末より先に入りうる
- ほかのキーで確定したとき、まだ差し替えが終わっていなければ、そのキーが先に入り、差し替えが後から入る

**確定まで貼らないアプリ**（`DeferredPasteApps`。アプリごとに `candPasteTiming` で変えられる）

- ターミナル: ターミナル（`com.apple.Terminal`）・iTerm2・Warp・Ghostty・tako・Alacritty・kitty・WezTerm・Hyper・Tabby
- チャット: Slack・Discord・LINE・メッセージ・Microsoft Teams・ChatGPT・Claude・Telegram・WhatsApp
- バンドル ID は手元の .app で確かめた（手元に無いものはコードに「未確認」と書いた）。一覧に無いターミナル・チャットは
  「入力欄を読めない」ので、たいてい確定まで貼らない側に落ちる

**そのほか**

- ペーストボードの控えは、除外の印（パスワード等）が付いていても取り消しのために読む（メモリの中だけ。保存も記録もしない）。256 MB を超えたら控えない
- 何も押さないまま 10 秒（`candIdleTimeout`）で確定して閉じる（仮に貼ったものは残る）
- 候補窓の数（行数・文字数）は一覧用の平文（先頭 1000 文字）から数える。切れていれば「+」を付ける

### コードの言語（`CodeLanguageDetector`）

- 見るのは一覧の平文（先頭 1000 文字）だけ。そこに手がかりがなく後ろにだけある長いコードは、言語が決まらない（色付けは最小限）
- 手がかりが少ない断片（1 行・数語）は決めない（`minimumScore` 4 点）。minify された JavaScript のように空白のない 1 行も決まらないことが多い
- 紛らわしい組は固有の手がかりで分ける: TypeScript は型の注釈（`: string`・`interface`）、C++ は `std::`・`#include <iostream>`、Kotlin は `fun`・`val`、Go は `package`・`:=`。どれもないと JavaScript・C・Swift 寄りになる
- Markdown のコードブロック（```lang）の言語名と shebang がいちばん強い。知らない言語名は「言語不明」
- 判定できる言語: Swift・JavaScript・TypeScript・Python・シェル・JSON・HTML・XML・CSS・Go・Rust・C・C++・Java・Kotlin・Ruby・SQL・YAML

### 色付け（`SyntaxHighlighter`）

- 字句だけを見る簡易なもの。正規表現のリテラル・文字列の中の式（`${…}`・`\(…)`）・JSX のタグは見分けない（文字列の色・ふつうの字になる）
- 「大文字で始まる名前は型」「`(` が続くか `.` の後ろの名前は関数」は試作と同じ決まり。定数（`MAX_SIZE`）も型の色になる
- 閉じない文字列は行末で、閉じないコメントは最後で止める（`"` や `/*` が 1 つあっても全体が文字列にならない。複数行を許すのは ``` ` ``` と 3 つ重ねの引用符だけ）
- シェルでは、プロンプトのある文字列の出力の行（プロンプトも続きでもない行）に色を付けない
- 言語不明のコードは文字列（`"` と ``` ` ```）・数・`//` と `/* */` のコメントだけに色を付ける

### プロンプトを外して貼る（`ShellPrompt` / `PastePipeline`）

壊さないことを優先し、迷う行は外さない。

- 外す: 行頭の `$ ` `% ` `❯ ` `➜ `、PS1（`user@host:~$ `・`[user@host dir]$ `・`user@host dir % `・`bash-3.2$ `・前に `(venv) `、oh-my-zsh の `➜  dir git:(main) ✗ `）、続き行の `> `（zsh の `dquote> ` なども。前の行が `\`・`|`・`&&` で終わるか、引用符・ヒアドキュメントが閉じていないときだけ）、全部の行が「# 既知のコマンド」のときの root の `# `
- 外さない: 出力の行（`$` や `%` で始まっていても、プロンプトの後ろに空白がなければ外さない。`$HOME`・`$(…)`・jQuery の `$(…)`）、行頭に空白のある行（字下げした `  $ ls` は外さない）、ほかにプロンプトの行があるときの `# `、`#!`、`➜  ~` のようにどこまでがプロンプトか分からない形
- 外した文字は文字の型（UTF-8・UTF-16）だけ。RTF・HTML（ターミナルが色付きで載せるもの）は元のまま書き戻すので、RTF・HTML を優先して読むアプリ（テキストエディットのリッチテキスト・メモなど）に貼ると「$ 」が残る。ターミナルとコードエディタは文字の型を読む
- 出力の行の頭が `$ ` のとき（`$ 5.00` のような金額）は、プロンプトと区別できず外れる
- ⇧↩（プレーンテキストで貼る）は外さない（元のまま貼る逃げ道。試作どおり）。候補窓から貼るときは外す（一覧から ↩ で貼るのと同じ）

### 一覧の表示

- カードのコピー方法は「キー」とだけ出す（⌘C と ⌘X を見分けて記録していない）
- ⌘⌫（履歴から削除）は、検索欄の「行頭まで消す」と同じキー。試作どおりにしたが、検索欄の編集を優先したくなったらフェーズ4で ⌥⌫ などに替える
- 検索欄で ⌘C・⌘X した文字も履歴に入る。パネルは元のアプリを前面のままにするので、コピー元は前面のアプリとして記録される
- コピー元のページは、題名を取り込んでいないので「ホスト　パス」で出す（試作は「題名　ドメイン」）。クエリ（`?` の後ろ）はトークンなどが入りうるので出さない。取れない項目（Firefox・ネイティブのアプリ・コピーボタン）では行ごと出さない
- ⌘Y のプレビューは先頭 2 万文字まで。見出しの行数・文字数は全文で数える（切ったときは「長いので先頭の … 文字だけを表示しています」を出す）
